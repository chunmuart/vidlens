# VidLens 前端 Soft UI 设计与开发规范

> 状态：当前生效  
> 适用范围：`client/` 下所有用户界面  
> 最近更新：2026-07-31

本文是 VidLens 前端的视觉与交互契约。它面向后续开发者和 AI 编程助手，目标是在增加上传方式、Agent 能力、评测视图或管理功能时，继续保持统一的 Soft UI 工作台体验，而不是逐页重新决定颜色和组件样式。

## 1. 产品与风格定位

VidLens 是视频内容理解和证据分析工作台，不是营销落地页。Soft UI 在这里用于降低长时间阅读和重复操作的视觉压力，同时用清楚的层级保留工具类产品所需的信息密度。

核心气质：

- 温和、现代、可信，避免赛博风和高饱和霓虹。
- 页面先强调任务与证据，再考虑装饰。
- 卡片、按钮和输入框具有可感知的实体层次，但阴影不能影响文字清晰度。
- 紫色表示主要操作，绿色表示成功，琥珀色表示处理中或提醒，玫红表示危险与失败。
- 大面积背景保持冷灰蓝，避免界面被单一紫色或暖色主导。

## 2. 文件与级联约定

当前样式加载顺序：

```text
client/src/style.css       全局重置和浏览器基础样式
client/src/App.vue         现有页面结构及历史兼容样式
client/src/soft-ui.css     当前生效的视觉系统，必须最后加载
```

入口文件 `client/src/main.js` 必须保持以下顺序：

```js
import './style.css'
import App from './App.vue'
import './soft-ui.css'
```

开发约束：

1. 新的视觉规则统一写入 `soft-ui.css`，不要继续向 `App.vue` 的历史样式块添加新主题色或新阴影。
2. 所有页面规则以 `.app-stage` 为作用域，避免污染 Markdown 渲染器或未来嵌入页面。
3. 优先扩展现有组件类；只有出现独立业务语义时才创建新类名。
4. 不使用行内 `style` 写固定颜色、阴影和圆角。动态进度宽度等数据驱动样式除外。
5. 不通过不断增加更高优先级选择器修复冲突。若新规则未生效，先检查导入顺序和既有选择器。

## 3. 设计令牌

设计令牌定义在 `client/src/soft-ui.css` 顶部的 `:root`。业务组件应引用令牌，不应复制十六进制颜色。

| 令牌 | 当前值 | 用途 |
| --- | --- | --- |
| `--bg-deep` | `#edf1f7` | 页面和侧栏底色 |
| `--surface-raised` | `#f8faff` | 凸起卡片、按钮和报告面 |
| `--surface-inset` | `#e9eef5` | 输入框、分段控件和进度槽 |
| `--accent-lime` | `#6267d9` | 主操作、选中、焦点和标题强调 |
| `--accent-purple` | `#b7527d` | 次要强调和危险度较低的导入操作 |
| `--accent-green` | `#238268` | 成功和系统可用状态 |
| `--accent-amber` | `#a96e18` | 处理中、等待和提醒 |
| `--accent-danger` | `#a3445c` | 失败、删除和错误 |
| `--text-main` | `#20283a` | 标题与正文主色 |
| `--text-sub` | `#5e6c82` | 辅助文字 |
| `--shadow-soft` | 双向柔和阴影 | 普通凸起控件 |
| `--shadow-inset` | 双向内阴影 | 输入框和按下状态 |
| `--focus-ring` | 紫色双层焦点环 | 键盘焦点 |

修改令牌时必须重新检查所有状态，不允许只观察首页。当前关键文字组合的 WCAG 对比度均达到 AA，最低值是辅助文字与页面背景的 `4.70:1`。

## 4. 空间、圆角和尺寸

- 页面内容最大宽度为 `1280px`，桌面水平内边距 `28px`，移动端 `16px`。
- 基础间距以 `4px` 为单位，常用值为 `8/12/16/20/24/28/32px`。
- 普通按钮和输入框圆角使用 `10-12px`，工作面和模态框使用 `16-18px`。
- 图标容器可使用 `12-18px` 圆角，但不得为了装饰额外套一层卡片。
- 所有可点击控件的最小触控尺寸为 `44 × 44px`。
- 视频封面必须声明稳定的 `aspect-ratio: 16 / 9`，列表卡片和操作区使用稳定网格，避免加载和状态变化导致跳动。

## 5. 层次与阴影

Soft UI 的层次由表面和阴影共同表达：

| 层次 | 表面 | 阴影 | 示例 |
| --- | --- | --- | --- |
| 页面层 | `--bg-deep` | 无 | 页面、侧栏底部 |
| 凸起层 | `--surface-raised` | `--shadow-soft` | 视频卡片、普通按钮 |
| 主工作面 | `--surface-raised` | `--shadow-float` | 上传区、BV 导入区 |
| 内凹层 | `--surface-inset` | `--shadow-inset` | 输入框、分段控件、进度槽 |
| 按下层 | 主色或凸起面 | `--shadow-pressed`/`--shadow-inset` | Active 状态 |

禁止项：

- 不使用无模糊的硬阴影。
- 不使用纯黑色、纯白大面积高对比块或黑色硬边框。
- 不使用背景模糊、景深模糊、装饰性光球或重渐变。
- 不在卡片中再放装饰性卡片；只有报告、对话轮次、工具 Trace 等真正独立的信息单元可以形成内层工作面。
- 同一个元素不同时叠加彩色外发光、厚边框和多层阴影。

## 6. 组件规则

### 6.1 按钮

按钮必须提供 Default、Hover、Active、Focus、Disabled 五种状态：

- Default：柔和凸起。
- Hover：阴影略增强并最多上移 `2px`，反馈应即时。
- Active：压回表面，使用内阴影或轻微 `scale(0.99)`。
- Focus：使用 `--focus-ring`，不能只改变颜色。
- Disabled：降低不透明度，禁止位移和 Hover 阴影。

主要命令使用紫色实心按钮；普通工具使用浅色凸起按钮；删除等危险操作只在需要时显示危险色。不要用圆角文字按钮替代用户熟悉的关闭、退出等图标命令。

### 6.2 输入框和文本域

- 使用 `--surface-inset` 和 `--shadow-inset` 表达可输入区域。
- Label 必须始终存在，Placeholder 不能代替字段名称。
- Focus 同时提高边界识别度并显示焦点环。
- 错误状态使用淡玫红背景和深玫红文字，错误信息放在字段附近。
- 文本域允许纵向调整，但要设置合理的最小高度。

### 6.3 分段控件

视频来源等互斥模式使用分段控件：外层内凹，当前项凸起。新增来源时保持选项文案短且互斥；选项超过三个时改用菜单，不要继续压缩触控区域。

### 6.4 视频卡片

- 标题最多一行并省略，完整名称放在 `title` 属性。
- 时间、来源和处理状态在同一元数据区域内。
- 主操作 `Video Agent` 使用紫色实心按钮，下载和提取属于普通工具按钮。
- 删除按钮桌面端可在 Hover/Focus 时出现，移动端必须始终可见。
- 新增操作后优先放入菜单；不要让卡片底部无限增加按钮列。

### 6.5 状态与反馈

| 语义 | 颜色方向 | 示例 |
| --- | --- | --- |
| 成功/完成 | 绿色 | 已完成、系统就绪 |
| 处理中/排队 | 琥珀色 | ASR、OCR、导入等待 |
| 失败/危险 | 玫红色 | 导入失败、删除、接口错误 |
| 选中/主流程 | 紫色 | 当前来源、Agent 主操作 |

状态不能只依赖颜色。始终同时提供文字、图标或形状差异，并在异步更新区域使用 `aria-live`。

### 6.6 Agent 侧栏

- 桌面端最大宽度约 `640px`，移动端占满视口。
- 报告正文是主要阅读面，Planner、Trace、工具调用和质量数据属于次级工作面。
- 对话轮次保持问题与答案的视觉分区，不能把所有内容放进一个连续大卡片。
- 标题必须允许省略，关闭按钮固定为 `44 × 44px`，不能被长文件名挤压。
- 关闭状态使用相对位移完全移出视口，不要写死与当前宽度相同的像素值。

### 6.7 模态框

模态框只用于登录、确认和必须打断当前流程的操作。遮罩使用半透明深灰，不使用背景模糊。主操作遵循普通按钮规则，关闭按钮使用固定图标按钮。

### 6.8 加载、空状态和错误

- 加载：保持原组件尺寸，显示阶段、进度和旋转指示，不让布局跳动。
- 空状态：说明当前没有内容并提供一个明确的下一步操作，不展示营销文案。
- 错误：使用淡玫红工作面，说明发生了什么和可执行的恢复动作。
- Skeleton 若以后加入，应使用表面明暗变化，不使用大面积模糊或闪烁动画。

## 7. 图标和文字

- 图标统一使用线性风格，推荐 `1.5-2px` 描边。
- 项目目前保留现有内联图标；若以后引入图标库，统一使用 Lucide，不混用多套图标语言。
- 图标按钮必须提供 `title` 或 `aria-label`。
- 页面标题保持短而明确，工作台内不使用营销式超大标题。
- 字号不随视口连续缩放。使用明确的桌面/移动断点字号。
- Letter spacing 保持 `0`，代码、BV 号和工具名可以使用等宽字体。

## 8. 响应式与可访问性

当前主要断点是 `760px`。新增组件至少验证：

- 桌面：`1440 × 900`。
- 移动：`390 × 844`。
- 页面无横向滚动。
- 文字不遮挡按钮、图标和后续内容。
- 网格在移动端变为单列，操作按钮保持至少 `44px` 高。
- 键盘可以访问所有按钮、输入框、Tab 和模态框关闭操作。
- 焦点清楚可见，颜色对比度达到 WCAG AA。
- 动效尊重 `prefers-reduced-motion`。

Hover 不能承载唯一功能。桌面 Hover 隐藏的删除按钮必须在移动端始终显示，并可以通过键盘 Focus 显示。

## 9. 新增功能的推荐流程

1. 先确认功能属于页面、工作面、重复卡片、模态框还是状态反馈，不要默认创建卡片。
2. 复用设计令牌和现有组件类，列出 Default/Hover/Active/Focus/Disabled/Loading/Error 状态。
3. 在 Vue 模板中先完成语义结构和可访问名称，再添加样式。
4. 样式写入 `soft-ui.css` 并使用 `.app-stage` 作用域。
5. 为固定格式内容设置网格、最小高度或 `aspect-ratio`，避免动态内容改变布局。
6. 运行生产构建并在桌面、移动端检查真实页面，而不是只看静态组件。
7. 检查控制台、横向溢出、触控尺寸、焦点、长中文标题、空状态、错误和加载状态。

新增组件示例：

```css
.app-stage .evidence-summary {
  padding: 20px;
  border: 1px solid rgba(255, 255, 255, 0.72);
  border-radius: 14px;
  background: var(--surface-raised);
  box-shadow: var(--shadow-soft);
  color: var(--text-main);
}

.app-stage .evidence-summary__filter {
  min-height: 44px;
  border: 0;
  border-radius: 10px;
  background: var(--surface-inset);
  box-shadow: var(--shadow-inset);
}
```

不要这样写：

```css
/* 随意引入新颜色、硬阴影、低对比文字和不稳定尺寸 */
.new-card {
  background: #fff;
  color: #aaa;
  box-shadow: 4px 4px #000;
  height: auto;
}
```

## 10. 交付检查清单

提交前逐项确认：

- [ ] 没有修改后端契约或通过前端伪造业务状态。
- [ ] 没有添加新的硬编码主题色和阴影。
- [ ] 新组件一眼可识别为当前 Soft UI，而不是独立模板。
- [ ] 按钮、输入、卡片、空状态、错误和加载状态使用同一视觉语言。
- [ ] 主次操作层级明确，紫色主按钮没有被大量滥用。
- [ ] 所有触控目标至少 `44 × 44px`。
- [ ] 键盘焦点可见，图标按钮有可访问名称。
- [ ] 桌面和移动端无横向溢出、遮挡和布局跳动。
- [ ] `prefers-reduced-motion` 下没有非必要动效。
- [ ] `npm run build` 通过，并检查真实页面截图与控制台。

## 11. 当前验证基线

2026-07-31 Soft UI 初版已完成以下验证：

- Vite 生产构建通过。
- `1440 × 900` 桌面端检查：本地上传、BV 导入、视频卡片和 Agent 侧栏。
- `390 × 844` 移动端检查：主页、视频操作和 Agent 报告。
- 页面无横向溢出，可见交互目标均不低于 `44px`。
- 关键文字与背景对比度达到 WCAG AA，最低为 `4.70:1`。
- 已处理侧栏关闭残留、长标题挤压关闭按钮和旧主题加载顺序问题。

这组结果是界面回归基线，不代表后端功能、Agent 准确率或性能指标发生变化。
